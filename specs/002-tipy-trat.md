# Обязательность и регулярность трат

## Для кого и зачем
Для владельца страницы учёта расходов, который хочет различать обязательные и необязательные, регулярные и нерегулярные траты.

## Что должно быть
- Существующие категории «Еда», «Транспорт», «Дом», «покупки» сохраняются.
- В форме добавления траты появляются 2 независимых поля выбора:
  - «Обязательность»: «Обязательная» или «Необязательная».
  - «Регулярность»: «Регулярная» или «Нерегулярная».
- Для новой траты нужно явно выбрать по одному значению в каждом поле. По умолчанию значения не выбраны; при попытке сохранить без выбора показать подсказку и не создавать запись.
- Допустимы все 4 сочетания признаков, независимо от категории. Признаки выбирает пользователь, страница не определяет их по названию категории или комментарию.
- В списке у каждой новой траты видны оба выбранных признака вместе с прежними данными.
- Оба признака сохраняются в localStorage и восстанавливаются после обновления страницы.
- После успешного добавления оба поля снова без выбора, чтобы следующую трату пользователь классифицировал явно.
- Старые записи без этих признаков продолжают загружаться и учитываться в итогах. Для отсутствующего признака показывать «Обязательность: не указана» или «Регулярность: не указана». Не присваивать старым тратам вымышленные значения.
- При сохранении новой записи старые записи, их суммы, категории, даты, комментарии и порядок сохраняются.
- Итог за текущий месяц по-прежнему включает все траты этого месяца независимо от обязательности и регулярности. Фильтр по периоду работает как раньше.

## Примеры
- Аренда: «Дом», «Обязательная», «Регулярная».
- Разовый необходимый ремонт: «Дом», «Обязательная», «Нерегулярная».
- Ежемесячная развлекательная подписка: «покупки», «Необязательная», «Регулярная».
- Разовая покупка для удовольствия: «покупки», «Необязательная», «Нерегулярная».
- Примеры иллюстрируют выбор пользователя, а не автоматические правила классификации.
- У старой траты на 5 000 ₸ без новых полей видны подписи «Обязательность: не указана» и «Регулярность: не указана»; её сумма входит в месячный итог как прежде.

## Ограничения
- Только HTML, CSS и JavaScript без библиотек, npm и внешних ресурсов; данные остаются в браузере.
- Интерфейс на русском, элементы управления не меньше 44px, страница помещается на ширине 375px.
- Регулярность — только признак записи: автоматическое повторение и создание будущих трат не входят в задачу.
- Новые фильтры, отдельные итоги по признакам, редактирование и удаление записей не входят в задачу.
- До изменения существующих файлов сохранить их датированные копии.
- Код реализации пишется после команды «делай». Когда функция реализована, обновить README.md и описать проверку.

## Готово, когда
- [ ] В форме есть 2 независимых поля с указанными подписями и вариантами; прежние 4 категории доступны.
- [ ] Можно сохранить каждое из 4 сочетаний признаков, и оба значения правильно видны в списке.
- [ ] Без одного или обоих значений запись не сохраняется; видна понятная подсказка, остальные введённые данные не теряются.
- [ ] После успешного добавления поля признаков снова требуют выбора.
- [ ] После F5 оба признака новых записей сохраняются.
- [ ] Записи, созданные до обновления, открываются без ошибок, остаются в прежнем порядке и учитываются в итогах. Отсутствующие признаки обозначены как неуказанные.
- [ ] После добавления новой траты и F5 старые данные остаются на месте.
- [ ] Траты 5 000, 2 500 и 12 000 за текущий месяц дают «19 500 ₸» при любых сочетаниях признаков.
- [ ] Фильтры периода, порядок новых записей сверху, проверка суммы и даты работают как прежде; NaN не появляется.
- [ ] На ширине 375px нет горизонтальной прокрутки, элементы выбора доступны и не меньше 44px.
- [ ] README.md описывает новые поля, поведение старых записей и шаги проверки.
